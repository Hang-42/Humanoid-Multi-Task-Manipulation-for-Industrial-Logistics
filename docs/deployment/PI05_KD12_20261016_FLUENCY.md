## Authorized offline changes (robot powered off)

1. `--sync-grasp` now splits at either hand's closing event. Each affected hand
   must complete its bounded closure-motion wait; simultaneous closes require
   both hands. Episode progress/reset is independent for the two hands.
   The old post-close arm prediction is still discarded before fresh inference.
2. In an already-closed episode, target jitter below 5 native position units
   retains the last applied model target. The comparison remains against that
   retained target, so small increases cannot accumulate into a large unguarded
   close. A significant increase triggers another wait. Reopening remains a
   model decision. No force, AUX or finger-position limit was increased.
3. Optional `--grasp-lookahead N` (0..10, default 0) permits the requested prefix
   to extend ONLY to the first nearby new model closing event. For steps=10,
   N=5 means at most 15 model frames, still bounded by five seconds of controller
   playback and the run deadline. No waypoint is skipped or synthesized.
   This may reduce repeatedly postponing a predicted close; improvement is
   not established until another live comparison.
4. Arm settling uses position total variation over >=120 ms of paired monotonic
   time rather than position differences divided by independently arriving MPC
   timestamp differences. It still requires all arm errors <=5 degrees and
   measured position-change rate <=5 degrees/second for 0.3 seconds, within
   three seconds. Frozen/duplicate controller clocks cannot qualify. It does
   not adopt the actual pose, relax an error limit, resend a trajectory or
   suppress the existing raw-velocity startup check.
5. New settling progress/timeout events include reference, measured position,
   per-joint error, worst joint, estimated rates and thresholds. Timeout also
   records raw joint velocities and actual camera evidence before stopping.
   The existing 10-degree/0.2-second tracking, standing, fall, motor, camera,
   controller-reference and acknowledgement protections remain active.

Qi's profile framework and unrelated concurrent edits are preserved. Core
changed Python files are synchronized to the local project. README and launcher
changes are applied to each workspace's own version, not copied over unrelated
profile support. No model, normalization, camera orientation, robot profile,
600-mA setting, recovery geometry, Git commit or push is changed here.
