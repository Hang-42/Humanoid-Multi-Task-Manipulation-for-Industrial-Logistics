## 初始化过渡参数

角度单位均为度，双臂向量顺序为左 7 关节、右 7 关节。

| 项目 | 当前设置 |
|---|---|
| 侧举姿态 | `[0,90,0,-5,0,0,0, 0,-90,0,-5,0,0,0]` |
| 折臂姿态 | `[-90,90,0,-90,0,0,0, -90,-90,0,-90,0,0,0]` |
| 每侧垂臂判定范围 | `[[-5,20],[-12,12],[-5,5],[-35,0],[-5,5],[-5,5],[-5,5]]` |
| 每侧姿态判定容差 | `[8,5,3,4,5,5,5]` |
| 向内收臂时腕部最大下降 | `0.55 m` |
| 折臂/内收速度限制 | `20°/s` |
| 胸前恢复速度限制 | `10°/s` |
| 胸前恢复中心线距离限制 | `0.08 m` |
| 恢复最大关节偏差 | `70°` |
| 恢复相对目标最大下降 | `0.35 m` |
| 恢复肘/腕/模型手端最大位移 | `0.35 / 0.40 / 0.45 m` |

适配时有一项收紧：旧 V53 肘关节垂臂判定范围的上限是 `+1°`，V55 URDF 的肘关节上限为 `0°`，
因此左右肘关节的判定上限改为 `0°`，避免接受模型关节限位以外的起始姿态。

现有侧举规划有独立的固定 `30°/s` 检查，不由 `safety.arm_speed_deg_s=20` 控制。
在厂商默认垂臂姿态下侧举峰值约 `21.094°/s`；折臂约 `14.063°/s`，内收约 `19.685°/s`。
本次沿用该阶段时间设置，未修改轨迹规划代码。

## Linker 抓握限幅

```json
"finger_caps": [50, 50, 50, 50, 50, 50, 50, 50, 50, 50]
```

顺序为左手 `thumb/index/middle/ring/pinky`，随后右手同样五个通道。
每个值表示兼容 ROS 接口 0–100 标度上的**最大屈曲位置指令**。`50` 是本次选取的联调默认值，
不是厂商标定的抓握限幅，也不代表 50% 握力、电流或确定的物理关节角。

模型输出闭合比例 0 时，屈曲通道目标为 0；输出 1 时，上述十通道目标上限为 50。
左右 `thumb_aux` 保留初始化值 `100`，不受这十个限幅控制。因此完全闭合请求实际映射为：

```json
[50,100,50,50,50,50, 50,100,50,50,50,50]
```

实际物体能否抓稳需通过联调确认；该默认值不能替代任务成功率验证。

## 离线检查与剩余项

使用备份 V55 URDF，在机身水平、腰关节为零、采用 URDF 工具参考点的条件下，检查了厂商默认垂臂姿态、
全部取垂臂范围下限、全部取上限三组起始姿态。侧举、折臂、折臂后内收及分段恢复路径共检查 1464 个轨迹采样点，
通过关节限位、阶段速度及腕部高度约束。内收最大腕部下降约 0.5013 m，小于配置的 0.55 m。
还检查了在胸前目标以及目标附近小偏差的两组恢复规划。

这些是模型和包络抽样检查，未穷举垂臂范围内所有组合，未验证物理手部/自碰撞/现场障碍物，也未验证实机跟踪。
具体结果见 [`v55_linker_transition_check.json`](v55_linker_transition_check.json)。

初始化过渡字段和抓握限幅现在都有数值；模型路径映射已填写，`validated=true` 的依据为用户指定联调默认通过。
使用前需声明 `PI05_WORKSTATION_IP`，加载器及部署脚本会将它解析为 `network.workstation_ip`。
工作站推理服务和图像链路正常是用户已确认事实，本轮没有重启或重新部署它们。
